# AI「赛马制」测试数据报告执行审查摘要

**审查结论：当前版本不具备直接提交条件，建议在补齐阻断项并完成一次交叉复核后再定稿。**

报告已形成项目A、C的负荷预测与部分设备参数预测链路，技术叙述中包含数据体检、掩码清洗、TFT日前预测、五随机种子、样本外窗口、无泄漏扰动和物理闭环等要素。项目A逐时结果、项目C逐时结果及部分设备指标已有数据，项目A仿真节能率填报为5.54%。这些内容可作为定稿基础，但现稿在完整性、评分风险和方法一致性上仍存在明显缺口。

首要问题是项目B几乎未形成可评审证据：表2逐时结果、表6B设备结果以及表8项目B节能结果均为占位符，极端工况相关表也有空缺，正文对B的分析很少。封面和基本信息表中的队伍名称同样未填写。上述内容属于直接影响受理、完整性检查或分项评分的阻断项，不能用推测值补齐，应由项目B负责人依据可追溯计算结果回填，并由负责人统一确认队名。

第二类风险集中在评分指标。项目C表6C中冷机功率第三项为24.33、水泵第三项为10.01；若该列确为MAPE，则分别明显高于题面所述“≤6%”目标，其中冷机偏差尤为突出。提交前必须回到原表核实列名、单位和计算口径；确认是MAPE后，应补充原因、改进结果或明确风险说明。表8只有项目A完整，项目C虽有控制策略描述但无节能数据，B/C及加权结果均空，无法支撑整体节能成效。

第三类风险是评测协议一致性。§2.2将TFT写为主线模型，而§3.1说明项目A考核日落在训练期内，表1改用仅含此前173个有效小时的“每日重训梯度提升树”。这一处理可能是为避免泄漏，但现稿未充分交代GBM配置、特征、重训边界、五种子含义及其与TFT结果的关系，容易被质疑为临时换模或口径不一致。建议保留事实，不改写数值，以一段可复现的协议说明消除歧义。

定稿顺序建议为：先补队名和项目B全链路数据；再补齐项目C与加权节能结果；随后核验项目C设备指标及评分阈值；最后统一模型口径、百分号、机构名称、表号和字数限制。由于仓库未提供原始 `.docx`，本次审查无法对122段、15表的完整原文和各节字数作精确验证，所有“待原稿复核”项应在源文件上完成终检。
