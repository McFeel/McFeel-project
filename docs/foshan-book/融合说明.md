# 融合说明：新产品发布报告并入《双碳目标下新型电力系统建设实践与探索：佛山篇》

## 一、做法（docx 深拷，不用 markdown 抽文本）

`build_merged_book.py` 直接在两个 docx 之间操作：

1. **定位薄占位块**：书稿正文中最后一处同时含「第三篇附」与「产品介绍」的段落为块起点；目录样式条目（TOC／目录 1—9）与含「对接：」的交叉引用行一律跳过。块终点为下一个同级或更高级标题、或「第×篇／附录×」。
2. **深拷报告全部内容**：产品报告正文的所有块级元素——段落（w:p）、表格（w:tbl）——逐个深拷到插入点，替换薄占位块。图片（a:blip／v:imagedata）按内容 SHA1 入书稿包并去重，外部超链接关系一并迁移；报告中的结构化文档域（w:sdt，如自动目录域）不拷入。
3. **版面照产品报告实际样式**：报告的 section 设置（pgSz／pgMar／cols／docGrid）套到书稿全部 section；报告的 styles.xml（docDefaults、latentStyles 及全部样式定义）合并进书稿，同 styleId 以报告为准——书稿既有正文、标题、图注随之自动改排，不自拟字体字号。报告 numbering 中的列表定义重映射 id 后并入书稿，不与书稿既有编号冲突。
4. **另存新文件**：结果写入 `--output`，两个输入文件只读。

## 二、不编造清单

- 脚本只搬运产品报告 docx 中的实际内容，不生成、不改写任何文字。
- 广东公司佛山项目案例板块（11 个项目）保持「内容待收集」，不动。
- 附录B 保持「待收集」，不补。
- 编委会名单不编造、不填入。

## 三、用法

```bash
python3 build_merged_book.py 源书稿.docx --report 产品报告.docx --output 融合后书稿.docx
python3 build_merged_book.py 源书稿.docx --dry-run   # 仅打印将替换的块，不写文件（无需 --report）
```

- 两个输入文件均只读打开，运行前后自动校验二者 SHA-256 一致。
- `--output` 与任一输入路径相同时拒绝执行；输出文件已存在时拒绝覆盖（除非显式 `--force`）。
- 找不到薄占位块时报错退出（退出码 3）并说明定位规则，不产出任何文件。
- 仅依赖 python-docx 与 Python 标准库。

## 四、测试（夹具）

云端没有两个真实输入文件时，用小图夹具验证（夹具不入库）：

- 书稿夹具：封面、卷首目录（含同名条目）、五篇、薄占位块、块前后各一条「对接：」交叉引用行、11 项目案例板块、附录A—D、书稿自有小图（红）与自有编号列表（numId 91）。
- 报告夹具：自定义页面（边距 2.0/2.2cm、docGrid linePitch 360）、自定义样式（Normal 仿宋 14pt、Heading 1 黑体 20pt、图注 楷体 9pt、docDefaults 仿宋）、正文段落、2x3 表格、两张小图（蓝/绿 PNG）、显式编号列表（numId 90）、外部超链接、一个 w:sdt 自动目录域。

验证点（31 项全部通过）：薄块替换且定位不受目录与「对接：」行干扰；报告段落／表格／图片／超链接／编号列表全部拷入且关系可解析；sdt 目录域未拷入；书稿与报告同名图片部件各自保留（报告 image1.png 自动更名 image2.png，不覆盖）；书稿版面（页边距、docGrid、Normal／Heading／图注样式、docDefaults）全部变成报告值；书稿既有编号（91）不变、报告编号重映射（90→101）且指向有效；11 案例板块、附录B、目录、书稿既有图　题注原样保留；两个输入文件 SHA-256 不变；同路径／已存在／缺 --report／报告缺失／无占位块五类拒绝路径均按预期退出；占位块位于文档末尾、书稿无 numbering 部件（新建路径）两个边界情形通过。
