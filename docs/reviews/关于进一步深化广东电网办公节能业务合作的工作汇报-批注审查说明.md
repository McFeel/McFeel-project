# 《关于进一步深化广东电网办公节能业务合作的工作汇报》批注审查说明

## 一、做法

对本件按已审 **20 条** 意见，用 **Word 批注（comment）逐条钉在正文对应句上**，
交付一份带批注的 Word 稿。**不改正文**：正文一个字都不动，问题、严重程度与改法只写在批注里；
**不另出清单体审查意见**，审查结论即以正文旁的批注呈现。

批注作者统一署名 **文秘**。每条问题一条批注，批注正文统一写「严重程度＋问题＋改法」，
与已审结论一致。

## 二、怎么生成

批注稿由脚本 [`add_gd_report_comments.py`](./add_gd_report_comments.py) 生成：

```bash
python3 docs/reviews/add_gd_report_comments.py 原稿.docx 批注稿.docx
```

- 输入：原稿 `docx`（正文不被修改）。
- 输出：带 `word/comments.xml` 的批注稿 `docx`，可直接在 Word 中打开、逐条查看与回复批注。
- 依赖：`python-docx`、`lxml`（`pip install python-docx lxml`）。

脚本只做三件事：在 `word/document.xml` 里把每条锚定文字用
`w:commentRangeStart`/`w:commentRangeEnd` 包起来并加 `w:commentReference`；
新增 `word/comments.xml`；在 `[Content_Types].xml` 与 `word/_rels/document.xml.rels` 登记
comments 部件。正文 run 仅按锚点边界切开，文字逐字保持不变。

原稿云端可能没有，可先用夹具自测 comments 部件是否正确：

```bash
python3 docs/reviews/test_add_gd_report_comments.py
```

该测试用 `python-docx` 造一份含全部锚点的样例正文，跑脚本后校验：20 条批注全部命中、
`comments.xml` 含 20 条且 `author=文秘`、`document.xml` 有 20 组批注区间与引用、正文零改动、
产物能被 `python-docx` 重新打开。

用以定位批注区间的关键词（斜杠/「或」表示候选，取先命中者；「首处即可」只钉首次出现处）。

| # | 严重程度 | 钉句锚点 | 问题与改法（批注正文要点） |
| --- | --- | --- | --- |
| 1 | 高 | 由南网能源公司承接 | 未经采购程序即预设承接主体与结果；改为「依程序参与框架采购、争取承接」。 |
| 2 | 高 | 严格按照贵司制度流程参与框架采购 | 对内汇报误用「贵司」、主体错位；去敬语并明确主体为我方（南网能源公司）。 |

## 四、约定

- 批注正文以 `add_gd_report_comments.py` 中 `COMMENT_SPECS` 为准，改稿改脚本后重跑即可重生成批注稿。
- 若原稿某句措辞与锚点不完全一致导致未命中，脚本会报出该条锚点，据实补对应锚点候选后重跑。
- 本说明与批注均为对内审查用，不进入对外发文正文。
