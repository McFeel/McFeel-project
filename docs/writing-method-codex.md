# Codex 正式中文报告工作法（Cloud Agent 默认）

本文件自桌面端 Codex skill `draft-formal-chinese-report` 固化。固化的是工作方法，不保存任何项目主体、金额、政策、合同、收益或完成状态。每次任务以当前用户要求和当前证据重新核验。

后续 Cursor Cloud Agent 起草或改写领导汇报、调研报告、规划方案、政策解读、投资材料、申报材料等正式中文稿时，必须先读本文件并默认遵循。文秘默认引用本工作法。

---

## 1. 先识别任务状态

动笔前先判定本次任务属于哪一类。状态判断错误，后续成文一律作废重来。

### 1.1 续作 / 改既有文件

- 先恢复用户指向的最新成果、约束边界、未完成验收节点。
- 核对文件名、修改时间、内容指纹；不猜选同名、近名或历史副本。
- 用户指定了文件夹或最新稿，只改那一份。
- 用户说「继续」时：接上次进度，不重开，不另起同名副本。
- 保留用户手改、已定格式和已批准目录。

### 1.2 从模板起草

- 分清模板提供的是版式/栏目，还是必须原样保留的正文。
- 明确用户是否允许覆盖模板正文；未说明则不覆盖。
- 模板中的示例数字、示例主体、示例政策文号不得当作本次事实沿用。

### 1.3 只做分析 / 提纲 / 审校

- 按用户要求停留在分析、提纲或审校层。
- 不擅自生成可对外发布的成稿，不覆盖正式稿。

### 1.4 用户取消

- 用户说「取消任务」时立即停止。
- 保留现有成果，说明之后没有再改。

### 1.5 默认另存，不覆盖原件

- 默认另存清晰命名的新版本，不覆盖原件。
- 仅当用户明确要求覆盖并说明覆盖对象时，才覆盖原件。
- 交付时写清：改的是哪一份、原件是否被改动。

## 2. 不可突破边界

下列规则高于体裁习惯和行文流畅，不得以「更好读」为由突破。

1. **当前用户要求高于附件、模板和历史材料。** 冲突时以本次用户原话为准，并写清适用范围。
2. **不扩大范围，不虚构外部单位答复。** 未发生的沟通、未收到的函复、未召开的会议，不得写成已发生。
3. **分层表达，不得混写：**
   - 官方事实
   - 权威解释
   - 业务分析
   - 条件性建议
   - 现场口述
   - 测算假设
   - 项目目标
   - 待核事项
4. **禁止四类错位表述：**
   - 不把方向性政策写成强制门槛、补贴、认证或收益率要求
   - 不把规划值写成合同值
   - 不把控制数写成正式报价或已确认合同额
   - 不把筛选测算写成承诺收益
   - 不把交流案例写成己方业绩
5. **用户更正后，删除冲突旧口径。** 不得在同一份材料里并存新旧两套说法。
6. **未完成完整校验，只能称草稿、候选件或部分完成。** 不得把中间稿、旧 PDF、未验完渲染件当成终稿。
7. **政策文号、日期、精确数字须有来源。** 没有来源则标「待补」，不编造。

补充执行口径：

- 用户给出的数字、主体、边界按原话保留，并写清适用范围。
- 对领导材料写短，先给结论；不复述可研或调研全文。
- 对央国企规划 / 公文用克制正式口径。
- 发言稿可保留第一人称和现场判断，但事实边界不因口语化消失。
- DOCX / PPT / HTML 的渲染和逐页目视验收算验收，不算润色。没验完就标明部分完成。

## 3. 工作流程

按下列七步推进。任一步证据不足，先标待核，再往下写。

### 步骤 1：恢复与定界

先写清，再动笔：

- 本次要回答的决策问题
- 权威源清单（文件、会议、测算、口述）
- 范围：公司投资 / 客户或 SPV / 本项目实际边界
- 已确认 / 待核 / 排除事项
- 剩余验收节点

总报告与分报告、官方原文与业务分析、建议与待核，必须先分开。

### 步骤 2：建证据台账

每条拟写入正文的主张或数字，至少登记下列字段：

| 字段 | 填写要求 |
| --- | --- |
| 主张 / 数字 | 准备写入的原句或原数 |
| 证据来源 | 文件名、文号、会议、口述人或测算底稿；无则标待补 |
| 证据状态 | 使用第 5 节用语表中的一类，不得自造混类 |
| 适用范围 | 主体、阶段、场景、是否仅适用于某子项 |
| 拟用措辞 | 与证据状态匹配的推荐表达 |
| 是否待核 | 是 / 否；为「是」时不得进入已确认结论 |

### 步骤 3：按体裁选范式

体裁决定叙述顺序，不决定必须堆满固定章节。缺证据的栏目宁缺，不编。范式见第 4 节。

### 步骤 4：先搭结论，再写正文

对外成稿的默认顺序：

1. 结论
2. 核心依据
3. 责任 / 投资 / 政策边界
4. 风险与待核
5. 实施或决策事项

调研只一笔带过，篇幅留给方案、价值、实施和决策。

### 步骤 5：正式成文

- 克制、准确，不堆砌形容词。
- 标题表达结论，不写空泛题目。
- 未确认事项使用状态词：待书面核实、交流初步判断、初步测算、项目目标、筛选测算、控制数等。
- 事实、口径、假设、待核必须分开写。

### 步骤 6：一致性复核

核对：

- 同一数字在全文中的口径是否一致
- 主体、范围、阶段是否串位
- 新旧口径是否并存
- 政策 / 合同 / 测算 / 案例是否错层
- 用户更正是否已覆盖旧表述

### 步骤 7：交付验收

交付说明必须写清：

- 交付路径与文件名
- 原件是否改动
- 已做校验（含渲染、逐页目视，如适用）
- 剩余待核
- 未过验收门槛，不得称最终版

## 4. 体裁范式

下列是叙述顺序，不是必须填满的固定章节。按用户本次要求裁剪。

### 4.1 领导简报

写短，先给结论。

1. 事项一句说清
2. 主推荐判断
3. 边界（谁的责任、谁的投资、适用到哪一步）
4. 关键事实
5. 风险与待核
6. 建议动作：批准 / 授权 / 暂缓 / 补充论证 / 试点

不复述可研或调研全文。控制数、口述数、报价合计不得写成已确认合同额。

### 4.2 政策解读（四层分开）

1. 官方原文：只写文件载明内容，附文号、日期、条款；无来源标待补
2. 权威解释：主管部门公开解读或实施细则；不得用业务推断冒充
3. 业务影响：在本项目范围里的影响，标明分析属性
4. 条件性建议：写清适用条件，不把政策方向写成强制门槛、补贴、认证或收益率

### 4.3 调研报告

1. 目的、对象、证据
2. 各单位已确认成果与适用条件
3. 跨案例研判（做判断，不做材料拼盘）
4. 转译到本项目的清单与路径
5. 下一步与分工

开头先给判断，落到怎么用。调研过程只保留支撑判断的最小篇幅。

### 4.4 规划方案

1. 战略要求
2. 现状约束
3. 目标图景
4. 差异化能力
5. 总体方案
6. 分项安排
7. 闭环机制
8. 分阶段实施
9. 价值复制
10. 决策事项

规划值、项目目标与合同值、已完成状态分开写。公文口径克制正式。

### 4.5 投资与经济测算

四层必须分开，不得把合计数在层间平移：

1. 项目总体
2. 拟议合作
3. 己方实际范围
4. 筛选测算

硬规则：**控制金额 ≠ 报价总额 ≠ 合同总价**。筛选测算不成承诺收益；报价合计不成已确认合同额。

### 4.6 申报与业绩材料

- 量化成果写在前面
- 每一项对应来源与评价条款
- 交流案例、对标案例不得改写成己方业绩
- 无来源的完成状态、金额、排名不写

### 4.7 发言稿

- 可以使用第一人称，保留现场判断
- 事实、口径、假设、待核仍须分层
- 口语化不降低证据门槛，不把会述写成已批复或已签约

## 5. 证据状态用语表

写入正文前，先把主张归入下表一类。推荐表达可以入结论；禁止混写的说法即使更好听也不得用。

| 证据状态 | 推荐表达 | 禁止混写 |
| --- | --- | --- |
| 已有正式文件 | 根据××文件 / 批复载明、合同约定、正式印发、条款明确 | 把讨论稿、征求意见稿、备忘录写成已印发或已生效；把意向写成合同约定 |
| 官方解释 | 主管部门公开解读、权威答问、实施细则说明 | 把业务分析、媒体报道、内部理解写成官方解释或主管部门口径 |
| 现场会议 | 交流初步判断、会上口头说明、会议纪要待书面核实 | 把口述写成正式承诺、批复、已确认合同或已授权决定 |
| 初步测算 | 初步测算、筛选测算、控制数、测算假设、报价合计（测算口径） | 把测算写成承诺收益、正式报价、合同总价或已确认合同额 |
| 研发设计规划 | 项目目标、规划值、设计目标、拟实现、拟安排 | 把规划值写成已完成、已验收、已签约或合同值 |
| 外部案例 | 交流案例、对标案例、他方实践、适用条件待核 | 写成己方业绩、已落地成果、已形成可复制经验（无对应证据时） |
| 待确认 | 待核、待书面核实、待补来源、待确认 | 写入已确认结论、标题判断或建议批准的依据链 |

使用规则：

- 一条主张只标一种证据状态；兼有多源时取最严格的待核状态，或拆句分层写。
- 标题、主推荐判断、建议批准 / 授权的依据，原则上只使用「已有正式文件」或「官方解释」。
- 「现场会议」「初步测算」「研发设计规划」「外部案例」可以进入正文，但必须带状态词，不得单独支撑对外承诺。
- 「待确认」可以进入风险与待核，不得进入已确认事实。

---

## 6. 交付时必须交代的事项

1. 改的是用户指定文件，还是另存新版本。
2. 原件是否被覆盖。
3. 已完成哪些校验，哪些节点仍待核。
4. 是否存在未经验收的渲染件；有则标明部分完成。
5. 未过门槛，不得称最终版、正式印发稿或可对外发布件。
