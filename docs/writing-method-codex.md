# 正式中文报告工作法（Cloud 引用版）

派单只引本路径，不粘全文。固化的是方法，不保存任何项目主体、金额、政策、合同、收益或完成状态。每次任务以 **本轮用户要求** 和 **本轮证据** 重核。

文秘默认引用本文件。领导汇报、调研、规划、政策解读、投资材料、申报材料等正式中文稿，先读再写。

---

## 引用约定

- Cloud 无跨会话记忆；需要本工作法时，在派单里写本文件路径。
- 写稿任务同时挂：本文件 + `docs/specialist-memory/文秘.md` + 底稿路径 + 本轮改口。
- 本轮禁止项优先于本文旧句。冲突时按本轮改口，并删并存旧说。

---

## 1. 先识别任务状态

状态判错，成文作废。

### 续作 / 改既有文件

- 先恢复用户指向的最新成果、约束、未完成验收点。
- 核文件名与内容，不猜选同名或历史副本。
- 指定了文件夹或最新稿，只改那一份。
- 用户说「继续」：接上次进度，不重开，不另起同名副本。
- 保留用户手改、已定格式和已批准目录。

### 从模板起草

- 分清模板是版式/栏目，还是必须原样保留的正文。
- 未说明可否覆盖模板正文，则不覆盖。
- 模板里的示例数字、主体、文号不得当本次事实。

### 只做分析 / 提纲 / 审校

- 停在用户要求的层。不擅自生成可对外成稿，不覆盖正式稿。

### 取消

- 用户说「取消任务」立即停，保留现有文件，说明之后没有再改。

### 默认另存，不覆盖原件

- 默认另存清晰命名的新版本。
- 仅当用户明确要求覆盖并指明对象时，才覆盖。
- 交付写清：改的是哪一份、原件动没动。

---

## 2. 不可突破边界

高于体裁习惯和行文流畅。

1. **本轮用户要求** 高于附件、模板、历史材料和本文件旧句。用户原话保留，并写清适用范围。
2. 不扩大范围，不虚构外部单位答复。未发生的沟通、函复、会议，不得写成已发生。
3. **分层，不得混写：** 官方事实 / 权威解释 / 业务分析 / 条件性建议 / 现场口述 / 测算假设 / 项目目标 / 待核。
4. **禁止错位：**
   - 不把方向性政策写成强制门槛、补贴、认证或收益率
   - 不把规划值写成合同值
   - 不把控制数、口述数、报价合计写成已确认合同额
   - 不把筛选测算写成承诺收益
   - 不把交流案例写成己方业绩
5. 用户更正后删除冲突旧口径，同一份材料不得两套说法并存。
6. **未完成完整校验，只称草稿、候选件或部分完成。** 中间稿、旧 PDF、未验完渲染件不是终稿。
7. 政策文号、日期、精确数字须有来源；无来源标「待补」，不编造。

补充：

- 对领导材料写短，先给结论；不复述可研或调研全文。
- 央国企规划 / 公文用克制正式口径。
- 发言稿可留第一人称和现场判断，事实边界不因口语化消失。
- DOCX / PPT / HTML 的渲染和逐页目视算验收，不算润色。没验完标明部分完成。
- 总报告 / 分报告、公司投资 / 客户或 SPV 边界、官方原文 / 权威解读 / 业务分析 / 建议，先分开再写。
- 调研只一笔带过，篇幅留给方案、价值、实施和决策。

## 3. 工作流程

任一步证据不足，先标待核。

1. **恢复与定界**：决策问题、权威源、范围（公司投资 / 客户或 SPV / 本项目实际边界）、已确认 / 待核 / 排除、剩余验收点。
2. **证据台账**：主张或数字登记来源、状态、适用范围、拟用措辞、是否待核。待核不得进入已确认结论。
3. **按体裁选范式**：缺证据的栏目宁缺不编。
4. **先搭结论再写正文**：结论 → 核心依据 → 责任/投资/政策边界 → 风险与待核 → 实施或决策。
5. **正式成文**：克制准确；标题表达结论；未确认事项带状态词。
6. **一致性复核**：数字口径、主体范围阶段、新旧口径、政策/合同/测算/案例是否错层。
7. **交付**：路径与文件名、原件是否改动、已做校验、剩余待核。未过门槛不得称最终版。

---

## 4. 体裁范式（叙述顺序，不是必填章节）

### 领导简报

写短，先给结论：事项一句说清 → 主推荐判断 → 边界 → 关键事实 → 风险与待核 → 建议动作（批准 / 授权 / 暂缓 / 补充论证 / 试点）。

### 政策解读

官方原文（文号、日期、条款）→ 权威解释 → 本项目范围内的业务影响（标明分析属性）→ 条件性建议。

### 调研报告

开头先给判断。目的与证据 → 已确认成果与适用条件 → 跨案例研判 → 转译到本项目的清单与路径 → 下一步。过程只留支撑判断的最小篇幅。

### 规划方案

战略要求 → 现状约束 → 目标图景 → 能力 → 总体方案 → 分项 → 闭环 → 业务阶段 → 价值 → 决策事项。规划值与合同值、已完成状态分开。

### 投资与经济测算

项目总体 / 拟议合作 / 己方实际范围 / 筛选测算，四层不得平移合计数。**控制金额 ≠ 报价总额 ≠ 合同总价。**

### 申报与业绩

量化成果在前，每项对应来源。交流案例、对标案例不得改写成己方业绩。

### 发言稿

可用第一人称和现场判断；证据门槛不降低；会述不成已批复或已签约。

## 5. 证据状态用语

| 证据状态 | 推荐表达 | 禁止混写 |
| --- | --- | --- |
| 已有正式文件 | 根据××文件 / 批复载明、合同约定、正式印发 | 讨论稿、备忘录写成已印发；意向写成合同 |
| 官方解释 | 主管部门公开解读、权威答问、实施细则 | 业务分析、媒体、内部理解冒充官方 |
| 现场会议 | 交流初步判断、会上口头说明、纪要待书面核实 | 口述写成承诺、批复、已确认合同 |
| 初步测算 | 初步测算、筛选测算、控制数、报价合计（测算口径） | 测算写成承诺收益或合同总价 |
| 研发设计规划 | 项目目标、规划值、拟实现、拟安排 | 规划值写成已完成、已验收、已签约 |
| 外部案例 | 交流案例、对标案例、他方实践、适用条件待核 | 无证据写成己方业绩或可复制经验 |
| 待确认 | 待核、待书面核实、待补来源 | 写入已确认结论或建议批准的依据链 |

一条主张只标一种状态。标题与建议批准的依据，原则上只用「已有正式文件」或「官方解释」。

---

## 6. 交付必须交代

1. 改的是指定文件还是另存新版本。
2. 原件是否被覆盖。
3. 已完成哪些校验，哪些仍待核。
4. 未经验收的渲染件须标明部分完成。
5. 未过门槛，不得称最终版、正式印发稿或可对外发布件。
