# 标题
如何通过优化 Grok Bot 工作流来提高大模型使用效率

# 正文
Grok Bot 直接写出来的文章，太烂。

让它一口气写正式长稿，出来的东西基本没法用。语气飘，结构散，也不像我自己会写的东西。

后来我换了个做法：先让顶级模型搭架子。

复杂稿、正式报告，先丢给 Fable 这类顶级模型，把骨架定下来。章节怎么铺，逻辑怎么走，边界卡在哪。骨架立不住，后面怎么改都是打补丁。写不动的模型，就别让它硬写全文。

但马上有现实问题：Fable 这类模型，token 和额度太贵，一篇稿子全程用它写，烧不起。

那就分开用。

最贵的模型只做框架规划。往骨架里填内容、写成能看的正式稿，换便宜的来，我这边用 Grok 4.6。贵的想结构，便宜的写句子。这才叫使用效率，不是死抠那点额度。

便宜模型也有坑：默认文风经常写不出像样的正式稿。

所以我把 Codex、ChatGPT 本地化的记忆和写作思路导进了 Cursor。这样 Cursor 里哪怕挂的是 Grok，出稿也尽量按 Codex 那套文风和思路来，不至于各写各的。

整个流程其实就几步。Grok Bot 直出太烂，所以让 Fable 这类顶级模型只搭架子；顶级模型太贵，不能全程用，填字就换 Grok 4.6；再把 Codex 那套习惯灌进 Cursor，让便宜模型也能写出像样的稿子。

Grok Bot 还留着，但干的活变了：指挥、拆任务、盯交接。长文别让它硬扛。

所谓优化工作流，说穿了就是搞清楚哪一段用哪一级模型。模型以后还会换，这条思路比盲目换更贵的模型管用。

——McFeel
